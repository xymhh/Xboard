# 落地出站引用（landing-outbound）

在节点「高级设置 → 自定义出站」里，用节点 ID 引用面板内的 SS 落地节点，
下发配置时自动解析为完整 Shadowsocks 出站，不用再手工抄地址、端口、密码。

## 用法

自定义出站里写引用（而不是完整出站）：

```json
[{"node_id": 60, "tag": "sg-ss"}]
```

- `node_id`：面板内落地节点的 ID（节点列表里能看到）。
- `tag`：可省略，默认 `landing-<node_id>`；路由规则里按这个 tag 引用。
- 已有的完整出站（带 `protocol` 的）不受影响，照常下发。
- 需要链式代理时可在引用里加 `proxy_tag`，解析后保留。

解析后的出站与手工写的格式一致（参考已在用的 `wa-ss`）：
地址、端口、加密方式取落地节点当前配置，密码用中转用户在该节点的
`serverKey:userKey`。落地节点改了配置，出站下次下发自动跟随。

## 插件配置

- **中转用户 ID**（默认 1）：出站以该用户的身份向落地节点认证。
  落地节点须授权该用户（分组与额度），否则落地侧认证失败。

## 容错

- 保存节点时校验引用：节点不存在、不是 SS、自引用、tag 重复或用了
  `direct`/`block` 都会当场报错，坏引用存不进库。
- 引用在保存后失效（例如落地节点被删）：下发时跳过该出站，并一并去掉
  指向它的路由规则，面板日志（`storage/logs/laravel.log`）留 warning；
  其余配置正常下发，节点不会因此整份配置失败。

## 注意

- v1 只支持 SS 落地节点；出站格式按 sing-box 内核（现有节点用的内核）。
- **停用或卸载插件前，先把各节点的引用改回完整出站**，否则引用会原样
  下发，节点校验失败、配置无法更新。
- 依赖面板核心的一行钩子：`ServerService::buildNodeConfig` 返回前
  `HookManager::filter('server.config.build', $response, $node)`。
  插件停用时该钩子无监听，不影响原有行为。

## 安装

1. 把本分支代码部署到面板服务器（或合并进你跑的版本）。
2. 管理端 → 插件，找到「落地出站引用」，安装并启用。
3. 在插件配置里确认中转用户 ID（默认 1 号用户）。
4. 在节点的自定义出站里写引用，保存后等节点轮询（60 秒内）生效；
   可在节点日志里确认出站已下发。
